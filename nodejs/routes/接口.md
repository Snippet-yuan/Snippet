# Snippet API 接口文档

- 基础路径：`http://localhost:8080/api/v1`
- 统一响应格式：`{ code, message, data }`，`code === 0` 表示成功
- 除登录/注册外，接口需在请求头携带 `Authorization: Bearer <token>`
- 通用中间件：`cors` 已开启，`express.json({ limit: "1mb" })`，静态资源 `GET /uploads/*` 映射到 `nodejs/uploads`
- 数据库同步：`sequelize.sync({ alter: true })`（开发环境自动同步表结构）

## 一、身份认证

### 1.1 注册

```
POST /api/v1/auth/register
```

**请求体（JSON）**

| 字段     | 类型   | 必填 | 说明                                 |
| -------- | ------ | ---- | ------------------------------------ |
| email    | string | 是   | 邮箱账号（唯一，自动 trim 并转小写） |
| password | string | 是   | 密码（bcrypt 加密存储）              |
| nickname | string | 是   | 昵称（自动 trim）                    |

**请求示例**

```json
{
  "email": "user@example.com",
  "password": "123456",
  "nickname": "昵称"
}
```

**成功响应（HTTP 201）**

```json
{
  "code": 0,
  "message": "注册成功",
  "data": {
    "token": "eyJhbGciOi...",
    "user": {
      "id": "1",
      "email": "user@example.com",
      "nickname": "昵称",
      "bio": "",
      "avatar": "",
      "background": "",
      "createdAt": "2026-09-02T12:00:00.000Z"
    }
  }
}
```

**失败响应**

| HTTP 状态码 | 场景                             |
| ----------- | -------------------------------- |
| 400         | email / password / nickname 为空 |
| 409         | 该邮箱已注册                     |

### 2.2 上传并更新头像（文件 URL）

```http
POST /api/v1/users/me/avatar
Authorization: Bearer <token>
Content-Type: multipart/form-data
```

**表单字段**

| 字段   | 类型 | 必填 | 说明                                 |
| ------ | ---- | ---- | ------------------------------------ |
| avatar | file | 是   | 图片文件，最大 5MB，仅允许 `image/*` |

**后端行为（`routes/users.js`）**

- 使用 `multer.diskStorage` 保存到 `nodejs/uploads/avatars`，文件名 `Date.now()-uuid + ext`
- 自动创建目录 `fs.mkdirSync(..., { recursive: true })`
- 生成可访问 URL：`${req.protocol}://${req.get("host")}/uploads/avatars/${filename}` 并写入 `users.avatar`
- `multer` 错误统一处理：`LIMIT_FILE_SIZE` → 413，其它 → 400

**成功响应（HTTP 200）**

```json
{
  "code": 0,
  "message": "头像更新成功",
  "data": {
    "id": "1",
    "email": "user@example.com",
    "nickname": "昵称",
    "bio": "记录生活里的小确幸。",
    "avatar": "http://localhost:8080/uploads/avatars/1700000000000-uuid.jpg",
    "background": "http://localhost:8080/uploads/backgrounds/xxx.jpg",
    "createdAt": "2026-09-02T12:00:00.000Z"
  }
}
```

**失败响应**

| HTTP 状态码 | 场景                             |
| ----------- | -------------------------------- |
| 400         | 未选择图片或文件类型不是图片     |
| 401         | 未携带 token、token 无效或已过期 |
| 404         | 用户不存在                       |
| 413         | 图片超过 5MB                     |

### 2.5 统一更新当前用户资料（文字+图片二合一）

```http
PATCH /api/v1/users/me
Authorization: Bearer <token>
```

**支持两种 Content-Type（同一接口）：**

1. `application/json`：仅更新文字字段
2. `multipart/form-data`：同时更新文字和图片（文件上传）

**语义规则（严格按你要求的规则实现）：**

| 情况                                      | 后端行为                                                |
| ----------------------------------------- | ------------------------------------------------------- |
| 字段不存在                                | 不修改                                                  |
| 字段存在且有有效值                        | 更新                                                    |
| 字段值为 `null` / `"null"` / `"__NULL__"` | 清空（`bio/avatar/background` 可清空，`nickname` 拒绝） |
| 字段为空字符串 `""`                       | 按业务拒绝（所有字段均拒绝空字符串）                    |

**字段说明**

| 字段       | 类型                 | 规则                                                                                                                 |
| ---------- | -------------------- | -------------------------------------------------------------------------------------------------------------------- |
| nickname   | string / null        | 存在则校验：trim 后非空，长度 1～30；null/空字符串均拒绝                                                             |
| bio        | string / null        | 存在则更新：null 清空为 ""，否则 trim 后长度 ≤200                                                                    |
| avatar     | file / string / null | file 优先（最大 5MB，需 `image/*`）；string 支持 `http(s)://` URL 或 `data:image/*;base64,`；null 清空；空字符串拒绝 |
| background | file / string / null | file 优先（最大 10MB，需 `image/*`）；string 为任意 URL；null 清空；空字符串拒绝                                     |

**示例 1：仅更新文字（JSON）**

```http
PATCH /api/v1/users/me
Authorization: Bearer <token>
Content-Type: application/json

{
  "nickname": "新昵称"
}
```

```http
PATCH /api/v1/users/me
Authorization: Bearer <token>
Content-Type: application/json

{
  "bio": "喜欢安静，偶尔出门看看风景。"
}
```

清空个性签名：

```json
{ "bio": null }
```

**示例 2：仅更新图片（multipart）**

```http
POST 实际为 PATCH + multipart
Content-Type: multipart/form-data

avatar: <file> (image/jpeg, ≤5MB)
```

**示例 3：文字+图片二合一（multipart，统一接口）**

```http
PATCH /api/v1/users/me
Authorization: Bearer <token>
Content-Type: multipart/form-data

nickname: 新昵称
bio: 慢热但真诚，欢迎交流。
avatar: <file> (≤5MB)
background: <file> (≤10MB)
```

只改昵称和头像，背景不动（不传 `background` 字段）：`background` 不会被修改。

**成功响应（HTTP 200）**

```json
{
  "code": 0,
  "message": "用户资料更新成功",
  "data": {
    "id": "1",
    "email": "user@example.com",
    "nickname": "新昵称",
    "bio": "慢热但真诚，欢迎交流。",
    "avatar": "http://localhost:8080/uploads/avatars/xxx.jpg",
    "background": "http://localhost:8080/uploads/backgrounds/xxx.jpg",
    "createdAt": "2026-09-02T12:00:00.000Z"
  }
}
```

**失败响应**

| HTTP 状态码 | 场景                                                                                                   |
| ----------- | ------------------------------------------------------------------------------------------------------ |
| 400         | 没有可更新的字段 / 昵称为空或超过 30 字符 / 个性签名超过 200 字符 / 头像/背景为空字符串 / 头像格式无效 |
| 401         | 未携带 token、token 无效或已过期                                                                       |
| 404         | 用户不存在                                                                                             |
| 413         | 头像超过 5MB / 背景超过 10MB / 整体表单超过 10MB                                                       |

```json
        "id": "98",
        "ownerId": "26",
        "ownerNickname": "木子同学",
        "ownerAvatar": "http://localhost:8080/uploads/avatars/xxx.jpg",
```

### 3.7 转发帖子

```http
POST /api/v1/posts/:postId/share
Authorization: Bearer <token>
Content-Type: application/json
```

请求体可选：

```json
{
  "target": "copy_link"
}
```

`target` 可选值为 `copy_link`、`message`、`external`，不传时默认为 `copy_link`。接口会校验帖子存在并将 `shareCount` 增加 1，返回帖子访问链接。

**成功响应**

```json
{
  "code": 0,
  "message": "转发成功",
  "data": {
    "postId": "35",
    "sharedBy": "26",
    "target": "copy_link",
    "shareCount": 3,
    "shareUrl": "http://localhost:8080/posts/35"
  }
}
```

### 3.8 获取帖子评论

```http
GET /api/v1/posts/:postId/comments?page=1&limit=20
Authorization: Bearer <token>
```

返回指定帖子的评论，按最新评论倒序排列。默认每页 20 条，最大 50 条。

### 3.8 发布帖子评论

```http
POST /api/v1/posts/:postId/comments
Authorization: Bearer <token>
Content-Type: application/json
```

请求体：

```json
{
  "content": "这张照片拍得真好看。"
}
```

评论内容会自动去除首尾空格，不能为空，最大 500 个字符。发布成功后会增加帖子的 `commentCount`。

## 四、帖子

### 4.1 主页帖子流（无限滚动）

```
GET /api/v1/posts?limit=20

```

**查询参数**

| 参数   | 类型   | 必填 | 说明                                                                              |
| ------ | ------ | ---- | --------------------------------------------------------------------------------- |
| limit  | number | 否   | 每批条数，默认 20，最大 50                                                        |
| lastId | number | 否   | 上一批最后一个帖子的 id；首次请求不传（返回最新），下拉加载时传（返回比它更早的） |

```json
  "data": {
```

**说明**

- 首次请求不带 `lastId`，返回最新的一批帖子
- 下拉加载时，把上一批 `items` 里最后一个帖子的 id 作为 `lastId` 传入
- 当返回条数 < `limit` 时，`hasMore: false`
- 排序：按帖子 id 倒序

覆盖 `users.bio` 字段，每个用户随机获得一条中文个性签名。

### 6.3 为指定用户生成帖子

为 `id=26, email=3527512976@qq.com` 生成 20 条包含多图、标题、文字、点赞、收藏和评论的帖子：


每条帖子 1～3 张图片（`picsum.photos`），并随机创建 `post_likes/post_favorites/comments` 记录，需至少 2 个用户。

### 6.4 为其他用户随机生成帖子

随机挑选多位用户（默认排除 `id=26`），每位用户生成 1～3 条帖子，附带点赞、收藏和评论：

```bash
cd nodejs
npm run seed:posts:others
# 等价于 node scripts/seedOtherPosts.js [帖子总数] [排除的用户ID]
```
